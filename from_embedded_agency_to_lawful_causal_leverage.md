# From Embedded Agency to Lawful Causal Leverage

## Steering, Realization Burden, Complexity Relocation, Environmental Delegation, and the Limits of Control

## Abstract

A familiar description of agency says:

```text
agent
→
chooses action
→
causes transition
→
produces outcome
```

This description is operationally useful but conceptually incomplete.

The agent is not outside the world selecting transitions from an external menu.

It is itself a physical subsystem whose observations, internal representations, goals,
decisions, actions, and consequences all occur within the same transition structure as
everything else.

This changes the interpretation of control.

An agent does not confer causal validity on a desired transition merely by selecting,
naming, requesting, or representing it.

Instead, it can only participate in trajectories that the underlying world actually
supports.

If a desired outcome is reachable, the agent may alter accessible conditions so that
the lawful evolution of the coupled system becomes more concentrated around that
outcome.

Thus:

\[
\boxed{
\text{control is not external command over law;
it is lawful steering from within law}
}
\]

This perspective also clarifies a recurring question about complexity.

A simple interface may hide an enormous realization burden.

A one-step command may invoke a mechanism whose construction required many layers of
materials, energy, control, stabilization, verification, and prior infrastructure.

Yet complexity is not literally conserved as one scalar quantity.

Regularity can allow many individually costly cases to share one generative mechanism.
A large bootstrap cost can be amortized across repeated use.
Environmental processes can supply dynamics that need not be reproduced locally.
A goal can sometimes be weakened or reframed so that fewer distinctions require
control.

The more defensible principle is therefore:

\[
\boxed{
\begin{array}{c}
\text{a reliable causal commitment cannot be made true by abstraction alone;}\\[3pt]
\text{the required relation must be realized somewhere in the coupled world.}
\end{array}
}
\]

The burden may be:

```text
satisfied
relocated
shared
amortized
preconstructed
delegated
supplied by the environment
or avoided by changing the requirement
```

but not created by semantics alone.

This document develops that view from embedded agency to causal leverage, conditional
control, complexity accounting, bootstrap infrastructure, environmental delegation,
and law-aligned interfaces.

---

# 1. Begin With the Embedded-Agent Constraint

Let the complete world state be:

\[
w_t\in W.
\]

Suppose an agent is a subsystem of that world.

Then one may decompose, for analysis:

\[
w_t=(e_t,a_t),
\]

where:

```text
e_t = environment-relative state
a_t = agent-relative state
```

But this decomposition does not place the agent outside the world.

Both components remain part of:

\[
W.
\]

The next state is generated by whatever transition structure the world realizes:

\[
w_{t+1}\sim P(\cdot\mid w_t).
\]

or, in a deterministic idealization:

\[
w_{t+1}=T(w_t).
\]

Therefore:

\[
\boxed{
\text{the agent is a participant in the transition law,
not an external exception to it}
}
\]

This is the first constraint on any theory of agency.

---

# 2. The External-Selector Picture Is an Abstraction

Ordinary control language often assumes a picture such as:

\[
x
\xrightarrow{\text{choose }u}
y.
\]

The notation is useful.

But it can suggest that the agent stands outside the dynamics and inserts:

\[
u
\]

as an independent command.

A more explicit description is:

\[
(a_t,e_t)
\rightarrow
(a'_t,e'_t)
\rightarrow
(a_{t+1},e_{t+1}).
\]

The event called:

```text
the agent selected u
```

is itself represented by some change in the agent and its coupling to the environment.

Thus:

\[
\boxed{
\text{selection is itself a realized transition}
}
\]

There is no need to posit a second causal layer that stands above the first one.

---

# 3. Action Is Not Outside Dynamics

Suppose a person presses a switch.

A high-level description is:

```text
person
→
press switch
→
light turns on
```

A more detailed trajectory contains:

```text
neural activity
→
muscle contraction
→
finger motion
→
switch displacement
→
circuit reconfiguration
→
electromagnetic dynamics
→
energy transfer
→
light emission
```

The action did not suspend the physical transition structure.

It was one organized part of it.

Thus:

\[
\boxed{
\text{agency is causal organization within the world,
not causal sovereignty over the world}
}
\]

---

# 4. Desire Adds No Causal Edge

Suppose an agent represents a goal:

\[
G.
\]

The presence of this representation does not imply:

\[
x\rightarrow G
\]

is realizable.

One may represent:

```text
instant teleportation
perfect prediction
zero-cost computation
unlimited energy
arbitrary state control
```

without obtaining the required transition structure.

Thus:

\[
\boxed{
\text{represented desirability}
\neq
\text{causal reachability}
}
\]

A goal can constrain the agent's search.

It does not constrain reality merely by being desired.

---

# 5. Absence Removes Whole Families of Realized Dynamics

Consider water.

If no water is present in the relevant system, then actual water-mediated dynamics are
not available there.

The statement is almost tautological:

\[
\text{no realized water}
\Rightarrow
\text{no realized water trajectory in that system}.
\]

Likewise:

```text
no conductive path
→
no current through that path

no actuator coupling
→
no actuation through that coupling

no receptor
→
no observation through that receptor

no fuel
→
no combustion of that fuel

no implementation
→
no execution of the claimed interface
```

The simplicity of these statements is important.

They reveal that operational capability always depends on some realized structure.

---

# 6. Possibility Is Not the Same as Presence

A transition may be permitted by broad physical law while unavailable in the current
local configuration.

For example:

\[
\text{water flow is physically possible}
\]

does not imply:

\[
\text{water is locally available}.
\]

Similarly:

\[
\text{semiconductor computation is physically possible}
\]

does not imply:

\[
\text{a processor is present}.
\]

Therefore distinguish:

```text
law-permitted possibility
local realizability
current reachability
available control
reliable invocation
```

These are different layers.

A useful hierarchy is:

\[
\boxed{
\text{possible}
\supseteq
\text{realizable}
\supseteq
\text{reachable}
\supseteq
\text{controllable}
\supseteq
\text{reliably exposed}
}
\]

---

# 7. Conditions Are the Operational Handle

Suppose an outcome:

\[
Y
\]

depends on conditions:

\[
C.
\]

An agent need not directly produce every internal step leading to \(Y\).

It may instead manipulate part of \(C\).

Schematically:

\[
\text{agent-accessible intervention}
\rightarrow
\text{condition change}
\rightarrow
\text{world dynamics}
\rightarrow
Y.
\]

Thus the practical control problem is often not:

> How do I directly manufacture the final state?

It is:

> Which accessible conditions influence the distribution of future states in a useful
> direction?

This yields:

\[
\boxed{
\text{effective action often targets conditions rather than outcomes directly}
}
\]

---

# 8. Control Is Better Modeled as Steering Than Selection

Suppose:

\[
P(Y\mid X)
\]

describes the uncontrolled outcome distribution.

An intervention:

\[
U=u
\]

is useful when:

\[
P(Y\mid X,do(U=u))
\]

differs in a task-relevant way.

A controller aims to choose accessible interventions so that probability mass shifts
toward a desired region:

\[
G\subseteq Y.
\]

Thus:

\[
P(Y\in G\mid X,do(U=u))
\]

should increase sufficiently.

This suggests:

\[
\boxed{
\text{control}
=
\text{lawful reshaping of reachable outcome distributions through available coupling}
}
\]

This is more precise than imagining an agent literally selecting the future state.

---

# 9. Deterministic Selection Is a Special Case

If the world is modeled deterministically:

\[
y=T(x,u),
\]

then a successful action may appear to select a unique successor.

But this is only the limiting case in which the relevant conditional distribution is
concentrated:

\[
P(Y=y\mid x,u)\approx1.
\]

The more general view remains:

\[
\text{intervention}
\rightarrow
\text{change in future distribution}.
\]

Therefore:

\[
\boxed{
\text{reliable selection can be treated as highly concentrated steering}
}
\]

This avoids making deterministic language conceptually primitive.

---

# 10. Steering Is Not Sovereignty

Even a very powerful controller cannot demand an arbitrary trajectory.

Its intervention set is limited:

\[
U\in\mathcal U.
\]

Its observation set is limited:

\[
O\in\mathcal O.
\]

Its reachable region is limited:

\[
R(x,\mathcal U).
\]

Its model is limited:

\[
\hat T\neq T_{\text{world}}
\]

in general.

Its energy, time, memory, and physical resources are limited.

Therefore:

\[
\boxed{
\text{control is conditional leverage,
not unrestricted authority}
}
\]

---

# 11. The No-Causal-Sovereignty Principle

The preceding sections motivate a stronger statement.

\[
\boxed{
\textbf{No-Causal-Sovereignty Principle}
}
\]

> An embedded agent does not possess the authority to make arbitrary transitions true.
> It can only participate in, redirect, stabilize, compose, or exploit transitions that
> remain supported by the causal structure of the world in which the agent itself is
> realized.

This does not deny agency.

It locates agency correctly.

---

# 12. What an Agent Can Possess Is Access, Not Law

A useful distinction is between:

```text
owning a law
```

and:

```text
having reliable access to a coupling.
```

A person does not possess electromagnetism.

But the person may possess a switch connected to a functioning electrical system.

A programmer does not possess the microscopic dynamics of semiconductor matter.

But the programmer may possess access to:

```text
ADD(x,y)
READ(i)
WRITE(i,v)
COPY(path)
```

A farmer does not possess photosynthesis.

But the farmer may control conditions that influence whether photosynthesis can proceed.

Thus:

\[
\boxed{
\text{practical capability often means access to stabilized causal leverage}
}
\]

rather than ownership of the underlying dynamics.

---

# 13. Causal Leverage

Suppose an accessible intervention has cost:

\[
C(u)
\]

and changes the probability of a desired outcome by:

\[
\Delta_G(u).
\]

A rough leverage quantity is:

\[
\Lambda(u)
=
\frac{
\Delta_G(u)
}{
C(u)
}.
\]

The exact numerator and denominator depend on the task.

The conceptual point is:

\[
\boxed{
\text{causal leverage is large when a small accessible intervention
reliably reorganizes a much larger future trajectory}
}
\]

Examples include:

```text
switch
→
electrical illumination

valve
→
large fluid-flow change

rudder
→
trajectory change

thermostat setting
→
distributed heating behavior

API call
→
large computational process
```

---

# 14. Causal Leverage Is Not Free Causation

A high-leverage intervention may look disproportionately powerful.

But the intervention usually couples into a larger pre-existing mechanism.

For example:

```text
small switch displacement
+
energized electrical infrastructure
→
large downstream effect
```

Remove the infrastructure and the same switch displacement loses the effect.

Therefore:

\[
\boxed{
\text{high leverage requires a receptive causal structure}
}
\]

The smallness of the trigger does not imply smallness of the total realization.

---

# 15. The Environment Can Supply the Mechanism

An agent does not need to locally reproduce every causal process it exploits.

Suppose the environment already realizes:

\[
C\rightarrow Y.
\]

If the agent can influence:

\[
C,
\]

then the environment can perform most of the subsequent transformation.

This produces:

\[
\boxed{
\textbf{Environmental-Delegation Principle}
}
\]

> When stable environmental dynamics already realize a useful transformation, an agent
> can gain capability by coupling to the conditions of that transformation instead of
> reproducing the full mechanism internally.

Examples include:

```text
sail
→
couple to wind

irrigation channel
→
couple to gravity and fluid flow

greenhouse
→
couple to biological growth

lever
→
couple geometry to force transmission

antenna
→
couple to electromagnetic propagation
```

---

# 16. Environmental Delegation Is Still Conditional

Delegation works only while the relevant environmental regularity remains available.

A sail without useful wind does not provide the same propulsion.

An irrigation channel without water does not irrigate.

A solar panel without sufficient radiation does not produce the same power.

Thus:

\[
\boxed{
\text{delegated capability inherits the validity conditions of the process it exploits}
}
\]

An interface can hide those conditions from ordinary use.

It cannot make them cease to matter.

---

# 17. Natural Processes Can Be Treated as Pre-Bootstrapped Infrastructure

From the perspective of a local agent, much of the world appears already operational.

Examples include:

```text
gravity
fluid dynamics
chemical bonding
phase transitions
photosynthesis
metabolism
ecosystem interactions
electromagnetic propagation
material elasticity
```

An agent entering such a world does not construct these regularities from scratch.

It discovers and exploits them.

This suggests:

\[
\boxed{
\text{the environment contains pre-existing causal infrastructure}
}
\]

The word **infrastructure** is relational here.

It means:

> a stable external process that can be coupled into a larger control architecture.

---

# 18. Engineering Adds Constructed Causal Infrastructure

Natural regularity may not expose a convenient control surface.

Engineering can then construct one.

For example:

```text
semiconductor dynamics
+
device geometry
+
thresholding
+
power supply
+
error margins
→
logic gate
```

Then:

```text
logic gates
+
clocking
+
state storage
→
processor
```

Then:

```text
processor
+
runtime
+
software
→
high-level operation
```

Thus:

\[
\boxed{
\text{engineering builds new leverage surfaces from already available regularity}
}
\]

The resulting higher-level operation can be novel without being causally ungrounded.

---

# 19. Creation Usually Means New Configuration, Not Ex Nihilo Causation

Ordinary language says:

```text
humans created the airplane
humans created the computer
humans created the city
humans created the program
```

This is valid at the level of organized configuration.

But it should not be confused with:

```text
humans created the underlying physical possibility from nothing
```

A more precise form is:

\[
\text{available matter}
+
\text{available energy}
+
\text{available regularity}
+
\text{organization}
\rightarrow
\text{new realized configuration}.
\]

Therefore:

\[
\boxed{
\text{creation in engineering is usually realization of a new configuration
inside an inherited possibility structure}
}
\]

---

# 20. An Interface Is a Handle on a Stabilized Relation

Suppose a system exposes:

\[
\operatorname{MOVE\_TO}(x).
\]

The symbol does not cause motion by semantic authority.

For the operation to be real, some mechanism must connect invocation to motion.

Thus:

\[
\operatorname{MOVE\_TO}(x)
\]

is best understood as a compact handle on a stabilized counterfactual relation.

Schematically:

```text
invocation
↓
controller
↓
actuators
↓
physical coupling
↓
trajectory
↓
feedback
↓
correction
↓
arrival region
```

The interface is powerful because the internal organization makes this large family of
trajectories behave like one reusable operation.

---

# 21. Simple Invocation Does Not Imply Simple Realization

Define:

\[
C_{\text{invoke}}
\]

as the cost borne by the caller to invoke an operation.

Define:

\[
C_{\text{realize}}
\]

as the broader cost of making the operation reliably true.

A mature interface may satisfy:

\[
C_{\text{invoke}}
\ll
C_{\text{realize}}.
\]

For example:

```text
turn switch
```

may require almost no reasoning from the caller.

But realization may depend on:

```text
generation
transmission
voltage regulation
wiring
protection
maintenance
materials
standards
monitoring
```

Therefore:

\[
\boxed{
\text{interface simplicity is compatible with deep realization complexity}
}
\]

---

# 22. Abstraction Does Not Make the Realization Burden Disappear

Suppose an interface promises:

\[
I:u\mapsto y.
\]

If the promise is operationally valid, then some causal organization must make the
relation hold sufficiently reliably.

A shorter name does not remove that requirement.

A smaller API does not remove it.

A more elegant model does not remove it.

A user forgetting the details does not remove it.

Thus:

\[
\boxed{
\textbf{Realization-Burden Principle}
}
\]

> A reliable causal commitment cannot be made true by abstraction alone. The relation
> required by the commitment must be realized somewhere in the coupled system or
> environment.

---

# 23. But Complexity Is Not One Conserved Scalar

It is tempting to strengthen the previous principle into:

\[
C_{\text{before}}=C_{\text{after}}.
\]

That is generally unjustified.

The word **complexity** may refer to:

```text
state-space size
description length
sample complexity
computational cost
control cost
verification cost
interface complexity
mechanism complexity
energy cost
coordination cost
dependency density
```

These quantities can move differently.

Therefore:

\[
\boxed{
\text{complexity is not generally one representation-independent conserved quantity}
}
\]

A useful accounting framework must state which burden is being measured.

---

# 24. What Persists Is a Causal Obligation, Not a Complexity Number

Suppose outcome \(Y\) requires condition family:

\[
K.
\]

If an interface promises \(Y\), then the realization must somehow ensure enough of:

\[
K
\]

to make the promise reliable.

One may:

```text
make the caller satisfy K
make the mechanism satisfy K
pre-establish K
use the environment to provide K
infer that K already holds
stabilize K with feedback
restrict the validity region to states where K holds
weaken Y so less of K is required
```

But simply ignoring \(K\) does not satisfy it.

Thus the more durable statement is:

\[
\boxed{
\text{causal obligations can be reorganized,
but unsupported obligations do not become supported by omission}
}
\]

---

# 25. Burden Can Be Relocated

Suppose:

\[
C_I
\]

is interface complexity and:

\[
C_M
\]

is mechanism complexity.

A design may intentionally reduce:

\[
C_I
\]

by increasing:

\[
C_M.
\]

For example:

```text
caller handles retries
```

can be replaced by:

```text
platform automatically retries safely
```

The caller reasons about less.

The platform does more.

Thus:

\[
\boxed{
\text{abstraction can relocate reasoning and stabilization burden}
}
\]

This is not disappearance.

It is responsibility transfer.

---

# 26. Burden Can Be Amortized

Suppose direct execution costs:

\[
c_d
\]

per use.

For \(n\) uses:

\[
C_{\text{direct}}=nc_d.
\]

Now suppose constructing infrastructure costs:

\[
C_B
\]

and each later invocation costs:

\[
c_i.
\]

Then:

\[
C_{\text{infra}}=C_B+nc_i.
\]

If:

\[
c_i\ll c_d,
\]

then for sufficiently large \(n\):

\[
C_{\text{infra}}\ll C_{\text{direct}}.
\]

Thus:

\[
\boxed{
\textbf{Bootstrap-Amortization Principle}
}
\]

> A costly causal structure can become economically simple at the interface when its
> construction cost is shared across many later uses.

The work did not vanish.

Its payment schedule changed.

---

# 27. Burden Can Be Shared Through Regularity

Suppose one million desired transitions are independent.

Then one may need one million separate specifications.

But suppose they satisfy:

\[
T_i=f(i;\theta).
\]

Now the shared parameterization:

\[
\theta
\]

constrains the entire family.

Thus:

\[
\boxed{
\text{regularity allows many transition commitments to share one generative structure}
}
\]

This can produce a genuine reduction in independent specification burden.

Nothing was hidden merely by notation.

The cases were structurally related.

---

# 28. Transition Count Is Not the Right Complexity Measure

Consider two systems with one million input-output pairs.

## System A

\[
y=2x.
\]

## System B

Each input maps to an unrelated random output.

Both contain one million concrete transitions.

Yet the first has a compact shared relation.

The second may require near-enumeration.

Therefore:

\[
\boxed{
\text{number of transitions}
\neq
\text{number of independently specified transition distinctions}
}
\]

The latter is often more relevant to learning, control, and representation.

---

# 29. Independent Distinctions Drive Burden

Suppose a family of transitions can vary independently.

Each independent variation may require additional information to:

```text
predict
distinguish
control
verify
stabilize
```

Shared structure reduces independence.

Thus a useful informal measure is:

\[
C_{\text{independent}}
\sim
\text{number of task-relevant distinctions that cannot be derived from one another}.
\]

This is not a universal complexity metric.

But it explains why:

```text
many instances
```

can remain easy when governed by:

```text
few reusable relations.
```

---

# 30. Structural Overhead Can Reduce Repeated Control Cost

A system may spend resources on:

```text
addressing
indexing
metadata
routing
error correction
schemas
types
protocols
```

These mechanisms increase implementation structure.

But they can drastically reduce repeated reasoning and control cost.

For example, an address decoder replaces separate wiring logic for each caller-visible
memory location with a reusable rule.

Thus:

\[
\boxed{
\text{more internal structure can produce less external control burden}
}
\]

This is not paradoxical once complexity is separated by layer and role.

---

# 31. Reuse Is a Form of Causal Compression

A reusable mechanism:

\[
M
\]

may support a family:

\[
\{T_1,T_2,\ldots,T_n\}.
\]

If callers can parameterize the mechanism:

\[
M(p_i),
\]

then one causal architecture spans many transitions.

This gives:

\[
\boxed{
\text{causal compression}
=
\text{one stabilized mechanism supporting many counterfactual uses}
}
\]

It is stronger than descriptive compression because the shared structure is executable.

---

# 32. Rich Possibility Is Not Control

Suppose a state has many possible successors:

\[
x\rightarrow\{y_1,\ldots,y_n\}.
\]

This does not imply an agent can reliably reach any chosen:

\[
y_i.
\]

The possibilities may depend on:

```text
hidden variables
uncontrollable disturbances
unavailable actuators
unknown timing
irreversible dynamics
resource limits
```

Thus:

\[
\boxed{
\text{possibility breadth}
\neq
\text{control breadth}
}
\]

A large repertoire is useful only to the extent that some of it is addressably
reachable.

---

# 33. Control Often Works by Removing Degrees of Freedom

Suppose many trajectories are physically possible.

Engineering often constructs constraints that eliminate or suppress most of them.

Examples include:

```text
rail
→
restricts vehicle trajectory

pipe
→
restricts fluid path

type system
→
restricts program states

protocol
→
restricts message sequences

fixture
→
restricts mechanical degrees of freedom

feedback controller
→
suppresses deviations
```

Thus:

\[
\boxed{
\text{useful control often increases reliability by reducing directly available freedom}
}
\]

---

# 34. Constraint Converts Possibility Into Reliability

Let:

\[
\Omega
\]

be a broad trajectory family.

Let:

\[
G\subseteq\Omega
\]

be the desired family.

Engineering may add constraints:

\[
K
\]

such that:

\[
P(\omega\in G\mid K)
\gg
P(\omega\in G).
\]

Thus:

\[
\boxed{
\textbf{Constraint-Steering Principle}
}
\]

> Control is often achieved by constructing conditions that suppress unwanted
> trajectories and concentrate lawful evolution into a smaller desired region.

This is more precise than saying that the controller freely selects one trajectory.

---

# 35. Manufactured Regularity Is Trajectory Funneling

A raw substrate may support:

```text
noise
variation
many microscopic states
many perturbation paths
```

An engineered mechanism introduces:

```text
thresholds
margins
feedback
isolation
error correction
validation
synchronization
```

so that many microscopic paths become operationally equivalent.

Schematically:

\[
\{\omega_1,\omega_2,\ldots,\omega_n\}
\rightarrow
z.
\]

Thus:

\[
\boxed{
\text{manufactured regularity is the stabilization of many lower-level trajectories
into a smaller family of reliable macroscopic outcomes}
}
\]

---

# 36. Feedback Makes Steering Persistent

Open-loop intervention may move the system toward a target once.

Feedback repeatedly compares:

\[
\text{observed state}
\]

with:

\[
\text{desired region}
\]

and adjusts interventions.

A generic loop is:

```text
observe
→
estimate
→
compare
→
intervene
→
observe again
```

Thus:

\[
\boxed{
\text{feedback converts one-shot causal influence into persistent trajectory correction}
}
\]

This is one of the main ways a fragile possibility becomes a reliable interface.

---

# 37. Reliability Is a Property of a Region, Not a Magic Label

An operation may work reliably only when:

```text
inputs are bounded
temperature is acceptable
power is available
latency remains within limits
materials remain intact
disturbances remain correctable
model error remains tolerable
```

Let:

\[
V
\]

denote this validity region.

Then a mechanism \(M\) realizes interface \(I\) only conditionally:

\[
M\Vdash_V I.
\]

Therefore:

\[
\boxed{
\text{reliable capability is always capability under conditions}
}
\]

---

# 38. A Larger Validity Region Is Genuine Power

Suppose:

\[
M_1\Vdash_{V_1}I
\]

and:

\[
M_2\Vdash_{V_2}I
\]

with:

\[
V_1\subset V_2.
\]

Then \(M_2\) supports the same apparent interface under more circumstances.

The interface may remain syntactically identical:

```text
MOVE_TO(x)
```

while the underlying engineering improves dramatically.

Thus:

\[
\boxed{
\text{robustness is partly expansion of the region over which causal leverage remains reliable}
}
\]

---

# 39. If the Relevant Regularity Changes, the Interface Loses Authority

Suppose the learned or assumed law is:

\[
\hat T.
\]

An interface is designed under:

\[
\hat T.
\]

But the realized dynamics become:

\[
T'.
\]

If:

\[
T'\not\approx\hat T
\]

over the intended region, then the old guarantee may fail.

No amount of semantic insistence repairs this.

Thus:

\[
\boxed{
\textbf{Law-Contingency Principle}
}
\]

# 101. Critical Predictions

The framework predicts:

1. A semantic operation whose causal support is severed will retain its label while
   losing the corresponding operational capability.

2. Two systems with equally simple interfaces may differ radically in hidden
   realization, maintenance, energy, and verification burden.

3. Lower caller-visible complexity will often correlate with greater stabilization or
   infrastructure burden somewhere else, but not with a fixed conserved total
   complexity.

4. Reusable regularity will allow many concrete transitions to share one mechanism,
   reducing independent specification and repeated control cost.

5. A system with a larger raw transition repertoire can be less controllable than a
   more constrained system if its transitions are not addressably steerable.

6. Adding constraints can increase effective capability by reducing unwanted
   trajectories and improving reliability.

7. A small intervention can have a large effect only when it couples into a
   sufficiently receptive causal structure.

8. Removing the supporting environment or infrastructure will reduce the leverage of
   an otherwise unchanged interface action.

9. Stronger guarantees will generally require stronger causal support, narrower
   validity regions, or greater stabilization and verification.

10. If observed dynamics leave an interface's validity region, the correct response is
    refinement, fallback, repair, or semantic restriction rather than insistence on the
    old guarantee.

11. Better representations can improve control only when they preserve or reveal
    distinctions connected to actual intervention leverage.

12. Better optimization cannot recover outcomes absent from the reachable region of
    the current action and mechanism space.

13. Approximation can make previously infeasible goals reachable by changing the
    required outcome region rather than violating the underlying dynamics.

14. Infrastructure with high bootstrap cost can dominate repeated direct action when
    its marginal invocation cost is sufficiently lower and reuse is sufficiently high.

15. Mature systems will increasingly expose small stable leverage bases rather than
    large catalogs of microscopic operations.

16. Greater autonomy will require not only stronger action selection but also the
    ability to refine representations, discover missing couplings, construct new
    mechanisms, and revise validity assumptions.

# 103. Open Questions

Several questions remain unresolved.

## 103.1 Is there a useful lower bound on realization burden?

For some specified operational promise, can one derive a representation-independent
minimum physical, informational, energetic, or control cost?

This would be much stronger than informal complexity relocation.

## 103.2 Which complexity measures compose?

Interface, mechanism, energy, inference, and verification costs interact.

A useful theory needs to specify which quantities can be added, amortized, or traded.

## 103.3 How should environmental delegation be priced?

If the environment supplies a large part of a mechanism, should the agent's capability
measure include only marginal intervention cost or the total external causal
infrastructure?

Different questions require different accounting boundaries.

## 103.4 How should causal leverage be normalized?

A small action may alter a huge trajectory while consuming large external energy.

A useful measure of leverage must distinguish:

```text
control information
trigger energy
total energy throughput
outcome magnitude
reliability
```

## 103.5 How does the framework change under genuinely nonstationary law?

Most engineering assumes stable regularity inside a validity region.

A world whose relevant transition structure changes unpredictably would weaken reuse,
semantics, abstraction, and control simultaneously.

## 103.6 What counts as the boundary of the agent?

If tools, infrastructure, external memory, institutions, and other agents are tightly
coupled, the effective control system may extend far beyond the biological or
computational core.

## 103.7 Can agency itself be measured as leverage?

One possibility is to define agency partly through the extent to which internal
represented distinctions systematically change future external trajectory
distributions.

This requires careful separation from mere causal influence.
